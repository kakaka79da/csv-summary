# 지사 구조 — 국내·해외 지사 설립

"지사를 여러 국가별로, 그리고 대한민국 안에서도 세울 수 있게" 라는 요청에 대한
구성 내역이다. 화면은 **조직 · 지사 패널 → 지사 및 서버** 에 있다.

---

## 1. 지사의 3종류

| 종류 | 뜻 | 만들어지는 방법 | 폐쇄 |
|---|---|---|---|
| `headquarters` (본사) | 회사의 뿌리. 하나만 존재한다. | 회사 창립 시 **자동 생성** | 불가 |
| `domestic` (국내 지사) | 같은 나라 안의 다른 지역 (서울 본사 + 부산 지사) | 대표가 설립 | 가능 |
| `overseas` (해외 지사) | 다른 나라 | 대표가 설립 | 가능 |

본사를 자동으로 만드는 이유: 사원이 처음 가입하면 아직 어느 지사에도 배치되지
않았는데, 소속이 없는 상태를 따로 두면 화면마다 예외 처리가 늘어난다. 그래서
**배치되지 않은 사원은 본사 소속으로 본다**(`branchId === null`).

## 2. 지사 상태

```
준비 중(preparing) ──[운영 시작]──▶ 운영 중(operating) ──[폐쇄]──▶ 폐쇄(closed)
```

- 설립하면 **항상 "준비 중"부터** 시작한다 — 사무실 계약·인원 배치 전에 목록에만
  올려 두는 실제 상황을 반영한다.
- 폐쇄해도 **기록은 지우지 않는다**. 인원·비용 이력이 그 지사에 붙어 있기 때문이다.
- 본사는 폐쇄할 수 없다(스토어에서 막는다).

## 3. 지사가 가지는 값

```ts
Branch {
  id, name                 // "부산광역시 지사"
  kind                     // headquarters | domestic | overseas
  country                  // "대한민국", "일본"
  region                   // 국내는 시·도, 해외는 도시
  serverRegion             // "ap-northeast-2 (서울)"
  timezone                 // "Asia/Seoul"
  currency                 // KRW | USD | JPY | EUR
  status, openedAt, note
}
```

**서버 리전을 지사와 함께 정하는 이유**: 나라마다 개인정보 국외 이전 규제가 다르다.
"어느 나라 사람의 데이터를 어느 나라 서버에 두는가"는 지사를 세우는 순간 결정해야
하는 값이라, 지사 레코드에 같이 넣었다.
⚠️ 다만 **이 프로토타입은 실제로 리전을 나눠 저장하지 않는다** — 표시용 값이고,
실제 분리 저장은 백엔드 항목이다(`docs/BACKEND-MIGRATION.md`).

## 4. 후보지 프리셋 (`src/data/seed.ts`)

- **국내 17곳** — 서울·부산·인천·대구·대전·광주·울산·세종 + 경기(수원)·강원(춘천)·
  충북(청주)·충남(천안)·전북(전주)·전남(여수)·경북(포항)·경남(창원)·제주.
  모두 서버 리전은 `ap-northeast-2 (서울)`, 통화는 KRW.
- **해외 13곳** — 일본(도쿄)·미국(로스앤젤레스/뉴욕)·싱가포르·베트남(호치민)·
  인도네시아(자카르타)·인도(뭄바이)·중국(상하이)·독일(프랑크푸르트)·영국(런던)·
  호주(시드니)·캐나다(토론토)·UAE(두바이). 각각 가까운 서버 리전·시간대·통화가
  함께 들어 있다.

프리셋을 고르면 서버 리전·시간대·통화가 자동으로 채워지고, 지사 이름만 원하는 대로
바꾸면 된다(비워 두면 "◯◯ 지사"로 만든다).

## 5. 규칙 (스토어에서 강제)

1. **대표만** 지사를 세우고, 상태를 바꾸고, 사원을 배치할 수 있다.
2. 같은 `country + region` 에 이미 (폐쇄되지 않은) 지사가 있으면 **중복 설립을 막는다**.
3. 본사는 폐쇄 불가.
4. 모든 설립·상태 변경·배치는 **감사 로그에 남는다**.

## 6. 사원 배치

- 조직 패널의 인간 사원 명부에서 사원마다 소속 지사를 고른다
  (`assignStaffToBranch`). 지사가 본사 하나뿐이면 드롭다운은 나타나지 않는다.
- 지사 카드에 **소속 사원 수**가 실시간으로 표시된다.
- **AI 직원은 지사에 배치하지 않는다.** 물리적 위치가 없고 회사 전체를 대상으로
  일하기 때문이다 — 필요해지면 그때 붙이는 편이 낫다고 판단했다.

## 7. 아직 하지 않은 것 (다음 단계 후보)

- 지사별 예산·비용 분리 (지금 비용은 회사 단위로만 집계한다)
- 지사별 근무 시간대 기준 근태 (지금은 시간대를 표시만 한다)
- 지사별 채팅방 자동 생성 (지금은 부서 채팅방을 수동으로 만든다)
- 오피스 화면(2D 맵)의 지사별 전환 — 지금 맵은 본사 하나만 그린다
- 지사 폐쇄 시 소속 사원 일괄 재배치 안내
