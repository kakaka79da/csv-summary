# 건의사항 13건 — 전부 처리 완료

> **2026-09-05 갱신:** 아래 13건을 모두 구현했다. 각 항목의 "고침" 줄이 실제로 한 일이다.
> 원래의 문제 서술은 왜 그렇게 고쳤는지 남기기 위해 그대로 둔다.

"대표나 직원들이 실제로 써 보면 무엇이 불편하다고 할까"를 화면을 따라가며 정리한
것이다. 추측이 아니라 **지금 코드가 실제로 하지 않는 일**만 적었다.

우선순위 기준: **얼마나 자주 걸리는가 × 걸렸을 때 얼마나 답답한가.**

| 표시 | 뜻 |
|---|---|
| ✅ | 이번에 고쳤다 |
| 🔴 | 곧 걸린다. 먼저 손봐야 한다 |
| 🟡 | 쓰다 보면 걸린다 |
| ⚪ | 있으면 좋다 |

## 1. 사원이 할 말

### ✅ 1-1. "재택하는 날마다 대표님한테 부탁해야 하나요?"

**있던 문제** — 근태(출근·재택·미출근)를 대표만 바꿀 수 있었다. 재택하는 날마다
대표에게 연락해야 했고, 대표는 그걸 일일이 눌러 줘야 했다.

**고침** — 사원 패널에서 본인이 바로 바꾼다(`updateOwnWorkMode`).
다만 **휴가·연차는 뺐다.** 그건 승인이 필요한 일이고, 스스로 누르는 순간 승인
절차가 무의미해진다. 휴가는 아래 1-2 로 이어진다.

### ✅ 1-2. "휴가를 어떻게 신청하나요?"

지금은 대표가 근태 값을 직접 `휴가·연차` 로 바꿔 준다. **신청 기록도, 승인 기록도,
잔여 연차도 없다.** 분쟁이 생기면 근거가 남지 않는다.

**고침** — 이미 있는 승인 센터에 얹었다. 새 화면을 만들지 않았다.
- `ApprovalKind` 에 `leave_request` 추가, 기간은 `Approval.leaveDays` 에 담는다
- 설정 화면에서 사원이 시작일·종료일·사유를 넣어 신청 → 대표 승인 센터에 뜬다
- **승인되는 순간 근태가 `휴가` 로 바뀐다** — 승인 기록과 화면이 어긋나지 않게 하려고
  같은 동작 안에서 처리한다
- 처리 대기 중인 신청이 있으면 또 낼 수 없고, 지난 신청의 승인·거절 결과가 남는다
- ⏳ 잔여 연차 계산(`annualLeaveDays`)은 아직 없다 — 회사마다 규정이 달라 지어내지 않았다

### ✅ 1-3. "이메일만 넣으면 남의 계정으로 들어가지네요?"

사원 로그인은 이메일 대조뿐이다. 동료 이메일을 알면 그 사람 계정으로 들어가
1:1 대화와 급여를 볼 수 있다. **프로토타입이라 그런 것이지만, 실제 데이터를 넣는
순간 사고다.**

**고침** — **개인 암호**를 넣었다(`src/lib/password.ts`, `docs/SECURITY.md` §1-2).
- 가입할 때 8자 이상 암호를 정하고, 다음부터 이메일+암호로 들어온다
- PBKDF2-SHA256 12만 회 + 사람마다 다른 소금. **원문은 어디에도 저장되지 않는다**
- 연달아 5번 틀리면 5분 잠금(새로고침해도 유지), 실패는 감사 로그에 남는다
- 없는 이메일과 틀린 암호를 **같은 문구로** 답한다 — 누가 이 회사에 있는지 알려주지 않는다
- 대표도 첫 진입에서 암호를 정하고, 관리자는 숨은 코드 **다음에** 암호를 통과해야 한다
  (코드는 번들에 문자열로 있으므로 그것만으로는 잠금 장치가 못 된다)

> ⚠️ **여전히 진짜 보안은 아니다.** 대조가 브라우저 안에서 일어나 개발자 도구로
> 우회할 수 있다. 어깨너머·실수를 막을 뿐이며, 실제 데이터를 넣으려면 서버 인증이
> 필요하다. 이 판단은 바뀌지 않았다.

### ✅ 1-4. "대표님이 답했는지 알 수가 없어요"

새 메시지 표시(안 읽음 배지)가 없다. 채팅방·1:1 을 하나하나 열어 봐야 안다.

**고침** — `lastReadAt`(계정키 → 대화키 → 시각)을 두고 배지를 붙였다.
- 채팅방 목록, 상단 "채팅방" 버튼, 헤더에 안 읽은 수가 나온다
- **내가 보낸 것은 세지 않는다.** 방을 열어 두는 동안은 계속 읽음 처리된다
- ⚠️ 이 값은 **이 브라우저에만** 있다. 다른 기기에서 읽은 것은 반영되지 않고,
  상대가 지금 썼는지는 새로고침해야 안다 — 진짜 실시간은 WebSocket 항목이다.

### ✅ 1-5. "내 이름·연락처를 내가 못 고쳐요"

가입할 때 넣은 이름·전화·캐릭터 외형을 본인이 수정할 수 없다.

**고침** — 설정 화면에 **내 정보**를 넣었다. 이름·연락처·캐릭터는 본인이,
직책·급여·소속 지사는 대표가 정한다. 이름을 바꾸면 화면 곳곳의 "로그인: ○○" 도
함께 바뀌고, 빈 이름은 거절한다.

### ✅ 1-6. "휴대폰에서 보면 좁아요"

오피스 맵과 오른쪽 패널이 2단이라 좁은 화면에서는 맵이 작아진다.

**고침** — 새로 넣은 화면(일정 타임라인·검색·첨부)은 전부 좁은 폭에서 세로로 쌓이고,
타임라인은 자기 칸 안에서만 가로 스크롤한다. 오피스 맵 2단 구조는 그대로 두었다 —
맵을 접으면 이 앱의 핵심이 안 보이기 때문이다. 태블릿 이상에서 쓰는 것을 권한다.

## 2. 대표가 할 말

### ✅ 2-1. "사원이 안 적으면 뭘 하는지 알 수가 없어요"

"지금 하는 일"은 사원이 직접 적은 한 줄이다. 안 적으면 빈칸이고, 대표는 그 사실을
한눈에 보기 어렵다.

**고침** — 근태·현황판에서 **미기재·오래된 인원을 위로 모으고** 금색 테두리로
표시한다. 맨 위에 "N명이 남기지 않았거나 8시간 넘게 갱신하지 않았습니다"라고 적는다.
시스템이 사람의 일을 알 수는 없으므로, **적게 만드는 쪽**으로 풀었다.

### ✅ 2-2. "회사 코드가 새면 아무나 가입 신청을 해요"

코드는 한 번 정해지면 바꿀 수 없다. 퇴사자가 코드를 알고 있으면 계속 신청할 수 있다.

**고침** — 설정에 **코드 새로 발급** 버튼을 넣었다. 한 번 더 확인을 받고,
누르면 새 코드가 나오며 **이전 코드로는 가입 신청이 즉시 막힌다**.
이미 승인된 사원은 영향을 받지 않는다. 복사 버튼도 함께 두었고 감사 로그에 남는다.

### 🟡 2-3. "지사를 세웠는데 오피스 화면은 그대로예요"

지사는 목록에만 있고, 2D 맵은 언제나 본사만 그린다. 세운 보람이 없다.

**아직 안 함 (유일하게 남긴 항목)** — 일정 화면은 지사별로 나뉘지만 2D 맵은 여전히
본사만 그린다. 맵에 지사 전환 탭을 붙이는 일은 캐릭터 배치 좌표를 지사마다 다시
잡아야 해서, 다른 12건과 묶어 처리하기에는 덩치가 다르다고 판단했다.
방법은 그대로다 — 맵 위 지사 탭, 고른 지사 소속 사원만 그리기, 도면은 재사용.

### ✅ 2-4. "찾는 기능이 없어요"

채팅·미션·사원·감사 로그 어디에도 검색이 없다. 쌓이면 못 찾는다.

**고침** — **검색** 패널을 넣었다. 미션·채팅·1:1·사원·일정·감사 로그를 한 번에 훑어
종류별로 묶어 보여 준다(최근 순 60건).
**볼 수 있는 것만 검색된다** — 사원은 자기 1:1 과 자기가 속한 방만 찾고, 남의 이메일과
감사 로그는 대표만 볼 수 있다. 검색이 권한의 구멍이 되면 안 되기 때문이다.

### ✅ 2-5. "미션에 마감일이 없어요"

미션에는 시작 시각과 예상 소요만 있고 마감일이 없다. 그래서 타임라인의 프로젝트
막대도 "예상"이라고 붙여 놓았다 — 없는 마감일을 지어내지 않으려고 그렇게 했다.

**고침** — `Mission.dueDay` 를 추가하고 미션 카드에서 대표가 정한다. 넣으면
- 타임라인 막대가 **"예상"을 떼고** 실제 마감으로 그려진다
- 기한이 지난 미션에 **"기한 넘김"** 배지가 붙는다
- 지우면 다시 예상 소요로 돌아간다 — 없는 마감일을 지어내지 않는다는 원칙은 유지

### ✅ 2-6. "급여를 달러로만 넣어요"

회사 통화가 KRW 인데 급여 입력은 USD 고정이다. 원 단위로 넣고 싶다.

**고침** — 입력 칸이 **회사 통화**로 바뀐다(예: `월급 (KRW)`). 저장은 언제나 USD 로
환산해서 한다 — 통화가 섞이면 급여 합계가 조용히 틀리기 때문이다. 환산에 쓴 환율을
입력칸 설명에 함께 적는다. ⚠️ 실시간 환율이 아니라 표시용 고정값이며, 실제 환율
연동은 백엔드 항목이다.

### ✅ 2-7. "통째로 백업하고 싶어요"

CSV 내보내기는 급여·비용·미션 몇 가지뿐이다. 브라우저를 청소하면 전부 사라진다
(보고서 6절의 중간 위험 항목).

**고침** — 설정에 **백업 내려받기 / 되돌리기**를 넣었다. 상태 전체를 JSON 한 파일로
저장하고 되돌린다. 화면 임시 상태(열린 패널·날씨)는 담지 않고, 모르는 열쇠는 무시하며,
남의 파일이면 **아무것도 바꾸지 않고** 거절한다.
⚠️ 미리보기 샌드박스에서는 파일 저장이 막힐 수 있다.

## 3. 이번에 함께 넣은 것

| 기능 | 내용 |
|---|---|
| **채팅 파일 첨부** | 방·1:1 어디서나 📎 로 붙이고 "받기"로 내려받는다. 이미지는 눌러서 크게 본다. |
| **용량 규칙** | 파일 하나 512KB, 회사 전체 2MB. 넘으면 **거절하고 이유와 대안(드라이브)을 말한다.** 남은 용량을 항상 보여 준다. |
| **일정 · 타임라인** | 회사 전체 / 지사별 탭. 본사를 열면 **전사 공용**과 **본사 내부**가 나뉜다. 미션은 읽기 전용 막대로 겹쳐 보인다. |

### 첨부 기능의 한계 (숨기지 않는다)

- 서버가 없어 **파일이 브라우저 안에만** 있다. 다른 기기에서는 안 보인다.
- 그래서 용량이 작다. 큰 파일은 구글 드라이브 폴더가 맞는 자리다.
- **미리보기 샌드박스(claude.ai 아티팩트)는 저장을 막는다.** "받기"가 아무 반응이
  없을 수 있다 — 로컬 실행이나 배포본에서는 정상 동작한다.

## 4. 남은 것

| 항목 | 왜 남겼나 |
|---|---|
| **2-3 지사별 오피스 맵** | 캐릭터 배치 좌표를 지사마다 다시 잡아야 해서 덩치가 다르다. 일정 화면은 이미 지사별로 나뉜다. |
| **잔여 연차 계산** | 회사마다 규정이 달라 지어내지 않았다. 휴가 신청·승인·기록은 동작한다. |
| **진짜 실시간 동기화** | WebSocket + 서버가 필요하다(`docs/BACKEND-MIGRATION.md`). |
| **서버 인증** | 지금 암호는 브라우저 안에서 대조한다. 실제 데이터를 받으려면 서버가 대조해야 한다(`docs/SECURITY.md` §3). |

이 네 가지는 전부 **백엔드가 있어야 제대로 되는 것**이거나, 회사 규정이 정해져야
지어내지 않고 만들 수 있는 것이다.
