# 쓰다 보면 나올 건의사항 — 예상 목록과 수정 제안

"대표나 직원들이 실제로 써 보면 무엇이 불편하다고 할까"를 화면을 따라가며 정리한
것이다. 추측이 아니라 **지금 코드가 실제로 하지 않는 일**만 적었다.

우선순위 기준: **얼마나 자주 걸리는가 × 걸렸을 때 얼마나 답답한가.**

| 표시 | 뜻 |
|---|---|
| ✅ | 이번에 고쳤다 |
| 🔴 | 곧 걸린다. 먼저 손봐야 한다 |
| 🟡 | 쓰다 보면 걸린다 |
| ⚪ | 있으면 좋다 |

---

## 1. 사원이 할 말

### ✅ 1-1. "재택하는 날마다 대표님한테 부탁해야 하나요?"

**있던 문제** — 근태(출근·재택·미출근)를 대표만 바꿀 수 있었다. 재택하는 날마다
대표에게 연락해야 했고, 대표는 그걸 일일이 눌러 줘야 했다.

**고침** — 사원 패널에서 본인이 바로 바꾼다(`updateOwnWorkMode`).
다만 **휴가·연차는 뺐다.** 그건 승인이 필요한 일이고, 스스로 누르는 순간 승인
절차가 무의미해진다. 휴가는 아래 1-2 로 이어진다.

### 🔴 1-2. "휴가를 어떻게 신청하나요?"

지금은 대표가 근태 값을 직접 `휴가·연차` 로 바꿔 준다. **신청 기록도, 승인 기록도,
잔여 연차도 없다.** 분쟁이 생기면 근거가 남지 않는다.

**제안** — 이미 있는 승인 센터에 얹는다. 새 화면을 만들 필요가 없다.
1. `ApprovalKind` 에 `leave_request` 추가
2. 사원이 시작일·종료일·사유를 넣어 신청 → 대표 승인 센터에 뜬다
3. 승인되면 근태가 자동으로 `휴가` 로 바뀌고, 종료일이 지나면 자동으로 돌아온다
4. `HumanStaffRecord` 에 `annualLeaveDays` / `usedLeaveDays` 를 넣어 잔여를 보여 준다

### 🔴 1-3. "이메일만 넣으면 남의 계정으로 들어가지네요?"

사원 로그인은 이메일 대조뿐이다. 동료 이메일을 알면 그 사람 계정으로 들어가
1:1 대화와 급여를 볼 수 있다. **프로토타입이라 그런 것이지만, 실제 데이터를 넣는
순간 사고다.**

**제안** — 백엔드 인증으로만 해결된다(`docs/SECURITY.md` §3).
그 전까지는 **실제 사원 데이터를 넣지 않는 것**이 유일한 대응이다.

### 🟡 1-4. "대표님이 답했는지 알 수가 없어요"

새 메시지 표시(안 읽음 배지)가 없다. 채팅방·1:1 을 하나하나 열어 봐야 안다.

**제안** — 서버 없이도 절반은 된다.
- `lastReadAt: Record<roomId | staffId, number>` 를 사원별로 저장
- 방 목록과 상단 버튼에 안 읽은 수를 배지로
- ⚠️ 다만 **상대가 지금 썼는지는 새로고침해야 안다.** 진짜 실시간은 WebSocket 항목.

### 🟡 1-5. "내 이름·연락처를 내가 못 고쳐요"

가입할 때 넣은 이름·전화·캐릭터 외형을 본인이 수정할 수 없다.

**제안** — 사원 패널에 "내 정보 고치기"를 넣는다. 이름·연락처·외형은 본인,
직책·급여·소속 지사는 대표. 경계를 그렇게 나누는 것이 자연스럽다.

### ⚪ 1-6. "휴대폰에서 보면 좁아요"

오피스 맵과 오른쪽 패널이 2단이라 좁은 화면에서는 맵이 작아진다.

**제안** — 좁은 화면에서는 맵을 접고 패널을 전체 폭으로. 지금 구조에서
`lg:` 분기만 손보면 되는 작은 작업이다.

## 2. 대표가 할 말

### 🔴 2-1. "사원이 안 적으면 뭘 하는지 알 수가 없어요"

"지금 하는 일"은 사원이 직접 적은 한 줄이다. 안 적으면 빈칸이고, 대표는 그 사실을
한눈에 보기 어렵다.

**제안** — 시스템이 사람의 일을 알 수는 없으니 **적게 만드는 쪽**으로 푼다.
- 근태·현황판에서 **미기재 인원을 위로 모아** 보여 준다
- 마지막 갱신이 오래됐으면 색으로 표시(지금도 "3시간 전"은 나오지만 눈에 안 띈다)
- 사원 화면에 하루 한 번 "오늘 뭐 하시나요?" 배너

### 🔴 2-2. "회사 코드가 새면 아무나 가입 신청을 해요"

코드는 한 번 정해지면 바꿀 수 없다. 퇴사자가 코드를 알고 있으면 계속 신청할 수 있다.

**제안** — 설정에 **코드 재발급** 버튼. 누르면 새 코드가 나오고 이전 코드는 죽는다.
지금 구조에서 `generateCompanyCode` 를 다시 부르고 감사 로그에 남기면 끝난다.

### 🟡 2-3. "지사를 세웠는데 오피스 화면은 그대로예요"

지사는 목록에만 있고, 2D 맵은 언제나 본사만 그린다. 세운 보람이 없다.

**제안** — 맵 위에 지사 전환 탭. 지사를 고르면 그 지사 소속 사원만 그린다.
맵 자체는 같은 도면을 재사용하면 된다(지사마다 다른 도면을 만들 필요는 없다).

### 🟡 2-4. "찾는 기능이 없어요"

채팅·미션·사원·감사 로그 어디에도 검색이 없다. 쌓이면 못 찾는다.

**제안** — 헤더에 통합 검색 하나. 이름·제목·본문을 훑어 종류별로 묶어 보여 준다.
데이터가 전부 메모리에 있으므로 서버 없이도 지금 만들 수 있다.

### 🟡 2-5. "미션에 마감일이 없어요"

미션에는 시작 시각과 예상 소요만 있고 마감일이 없다. 그래서 타임라인의 프로젝트
막대도 "예상"이라고 붙여 놓았다 — 없는 마감일을 지어내지 않으려고 그렇게 했다.

**제안** — `Mission` 에 `dueDay` 를 추가한다. 넣는 순간
- 타임라인 막대가 "예상"이 아니라 실제 마감이 되고
- 늦은 미션을 빨갛게 표시할 수 있고
- 일정 화면과 미션 화면이 같은 것을 가리키게 된다

### 🟡 2-6. "급여를 달러로만 넣어요"

회사 통화가 KRW 인데 급여 입력은 USD 고정이다. 원 단위로 넣고 싶다.

**제안** — 입력도 회사 통화로 받고, 내부 저장만 USD 로 환산한다.
환율은 설정에 고정값으로 두고 언제 기준인지 함께 적는다(실시간 환율은 백엔드 항목).

### ⚪ 2-7. "통째로 백업하고 싶어요"

CSV 내보내기는 급여·비용·미션 몇 가지뿐이다. 브라우저를 청소하면 전부 사라진다
(보고서 6절의 중간 위험 항목).

**제안** — 설정에 **전체 내보내기 / 불러오기**. 상태를 JSON 한 파일로 저장하고
되돌린다. 서버가 생기기 전까지의 유일한 안전장치다.

## 3. 이번에 함께 넣은 것

| 기능 | 내용 |
|---|---|
| **채팅 파일 첨부** | 방·1:1 어디서나 📎 로 붙이고 "받기"로 내려받는다. 이미지는 눌러서 크게 본다. |
| **용량 규칙** | 파일 하나 512KB, 회사 전체 2MB. 넘으면 **거절하고 이유와 대안(드라이브)을 말한다.** 남은 용량을 항상 보여 준다. |
| **일정 · 타임라인** | 회사 전체 / 지사별 탭. 본사를 열면 **전사 공용**과 **본사 내부**가 나뉜다. 미션은 읽기 전용 막대로 겹쳐 보인다. |
| **사원 근태 자기 변경** | 위 1-1. |

### 첨부 기능의 한계 (숨기지 않는다)

- 서버가 없어 **파일이 브라우저 안에만** 있다. 다른 기기에서는 안 보인다.
- 그래서 용량이 작다. 큰 파일은 구글 드라이브 폴더가 맞는 자리다.
- **미리보기 샌드박스(claude.ai 아티팩트)는 저장을 막는다.** "받기"가 아무 반응이
  없을 수 있다 — 로컬 실행이나 배포본에서는 정상 동작한다.

## 4. 다음에 손댈 순서 (제안)

1. **1-2 휴가 신청 절차** — 근태 자기 변경까지 왔으니 그다음이 자연스럽다. 승인 센터에 얹으면 된다.
2. **2-2 회사 코드 재발급** — 반나절. 보안 구멍 하나가 닫힌다.
3. **2-1 미기재 인원 강조** — 대표가 매일 보는 화면이 바로 좋아진다.
4. **2-5 미션 마감일** — 일정 화면과 미션 화면이 하나로 이어진다.
5. **1-4 안 읽음 배지** — 서버 없이 절반은 되고, 나중에 실시간이 붙으면 그대로 쓴다.

1-3(인증)과 진짜 실시간은 백엔드 항목이라 여기 순서에 넣지 않았다 —
`docs/BACKEND-MIGRATION.md` 를 따른다.
