# 로컬 시각 · 현위치 날씨 효과

"노컬타임(로컬 시각) 현위치 날씨를 불러와서 GPS 위치에 맞게 효과로 보여 줘 —
눈이 내리거나 비가 오거나" 요청에 대한 구성 내역이다.

화면에서 보는 곳: **헤더의 시각/날씨 배지** (클릭하면 설정 패널) 와
**오피스 2D 화면 전체**.

---

## 1. 흐름

```
브라우저 위치 권한 ──▶ 좌표(소수점 2자리로 반올림) ──▶ Open-Meteo 호출
      │                                                     │
      └─(거부/실패)──▶ 기본 좌표(서울)                        ▼
                                                    WMO 코드 → 6가지 상태
                                                             │
                                        스토어 weather ◀──────┘
                                                             │
                              오피스 SVG 위에 비/눈/안개/번개/어둠으로 그린다
```

- 관측 갱신 주기: **10분**. 위치는 **한 번만** 물어보고 재사용한다(갱신할 때마다
  권한 창이 뜨면 성가시다).

## 2. 왜 Open-Meteo 인가

**API 키가 필요 없기 때문이다.** 이 프로젝트는 "비밀값을 프론트엔드 번들에
넣지 않는다"를 원칙으로 하고 있어서, 키를 요구하는 서비스(OpenWeatherMap 등)는
백엔드 프록시가 생기기 전에는 쓸 수 없다. Open-Meteo 는 키 없이 브라우저에서
바로 부를 수 있으므로 원칙을 깨지 않고 실제 관측값을 쓸 수 있는 유일한 선택지였다.

호출 URL에는 좌표·요청 항목·시간대만 들어간다(`buildForecastUrl`). 테스트에서
URL 에 `key` 라는 글자조차 붙지 않는 것을 검증한다.

## 3. 위치 정보 취급

- **정확한 GPS 좌표는 저장하지 않는다.** `roundCoord` 로 소수점 2자리(약 1km)
  까지만 남긴다. 날씨는 1km 단위면 같은 값이 나오므로 정밀도를 더 가질 이유가 없다.
- 좌표는 **브라우저 → Open-Meteo** 로만 나간다. 이 앱에는 서버가 없으므로
  어디에도 기록되지 않고, 새로고침하면 사라진다(`weather` 는 localStorage 에
  저장하지 않는다).
- 화면에는 언제나 **값의 출처**를 함께 표시한다 — 현위치 관측 / 기본 위치(서울) /
  수동 고정 / 아직 못 받아옴.

## 4. 못 받아올 때 (숨기지 않는다)

| 상황 | 화면 |
|---|---|
| 위치 권한 거부 | 서울 좌표의 실제 날씨 + "위치 권한이 거부되어 기본 위치(서울)…" |
| 위치 응답이 아예 없음 | 8초 후 스스로 끊고 같은 기본 위치 처리 |
| 외부 통신 차단 | 날씨를 바꾸지 않고 "받아오지 못했습니다" 문구만 남긴다 |

받아오지 못했을 때 **아무 날씨나 지어내지 않는다**. 대신 헤더 패널에서 사람이
직접 날씨를 고를 수 있고(테스트용), 고른 동안에는 화면 곳곳에
"수동 고정 — 실제 값 아님"이라고 표시한다.

> ⚠️ claude.ai 아티팩트 미리보기는 샌드박스가 위치·외부 통신을 모두 막는다.
> 거기서는 실제 날씨가 뜨지 않는 것이 정상이며, **수동 고르기로 효과를 확인**하면
> 된다. 실제 관측은 `npm run dev` 나 HTTPS 로 배포한 곳에서 동작한다
> (위치 API 는 보안 컨텍스트에서만 동작한다).

## 5. 날씨 → 효과

WMO 코드를 6가지로 묶는다(`wmoToCondition`). 세부 코드가 40개 넘지만 화면 효과는
6개뿐이라 과감히 묶었다 — 이슬비·비·소나기·어는 비는 모두 '비'다.

| 상태 | 화면 |
|---|---|
| 맑음 | (낮에는) 아무 효과 없음 |
| 흐림 | 옅은 구름 층 + 살짝 어둡게 |
| 안개 | 두꺼운 부연 층 |
| 비 | 기울어진 빗줄기 120개 + 어둡게 |
| 눈 | 좌우로 흔들리며 내리는 눈송이 90개 |
| 뇌우 | 굵은 비 140개 + 간헐적 번개 섬광 |

여기에 **시간대**가 겹친다(새벽/낮/해질녘/밤). 밤에는 화면 전체에 짙은 남색 막이
깔리고 입자 수를 줄인다 — 어두운 화면에서 입자가 과하게 도드라지지 않도록.

시간대는 기기의 로컬 시계로 정하되, 실제 관측이 있으면 관측지의 낮/밤을 함께
본다. 둘이 어긋나면(북유럽의 밝은 여름밤 등) 극단으로 가지 않고 '해질녘'으로
완충한다(`resolvePhase`). 관측값이 아예 없으면 시계만 믿는다(`phaseFor`).

## 6. 성능 — 왜 CSS 애니메이션인가

입자는 최대 140개다. 이 앱은 이미 `requestAnimationFrame` 으로 시뮬레이션 tick 을
돌리고 있어서, 입자까지 React 상태로 움직이면 매 프레임 수백 개 노드를 다시
만들게 된다. 그래서 **움직임은 전부 CSS 키프레임**(`src/index.css` 의 `wx-*`)에
맡기고 React 는 한 번만 그린다. 배치는 시드 기반이라 다시 그려도 흔들리지 않는다.

- SVG 요소의 CSS `transform` 에서 px 는 user unit(= viewBox 타일 수)으로
  해석되므로, 낙하 거리를 타일 수로 그대로 쓴다.
- `animation-delay` 에 음수를 줘서 화면이 열리자마자 이미 흩어져 내리는 상태로 보인다.
- `prefers-reduced-motion: reduce` 를 켠 사용자에게는 애니메이션을 멈춘다.
- 헤더에서 **화면 효과 끄기**로 언제든 끌 수 있다(저사양 기기·멀미 대응).

## 8. 아직 하지 않은 것

- **지사별 날씨** — 지금은 보는 사람의 현위치 하나만 그린다. 지사마다 좌표를
  가지고 있으므로(`Branch.timezone`), 지사를 고르면 그곳 날씨로 바꾸는 것은
  자연스러운 다음 단계다.
- 계절 연출(벚꽃·낙엽), 기온에 따른 캐릭터 옷차림 변화.
- 날씨에 따른 업무 연출(비 오는 날 출근이 늦어진다 등) — 실제 근태와 섞이면
  혼란스러우므로 일부러 넣지 않았다.
