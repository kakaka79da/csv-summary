# AI 팀원 시스템 — 셋업 키트

3090 1장 + 윈도우(WSL2) 환경에서 n8n + Claude API + 로컬 LLM으로
역할별 AI 에이전트 팀을 구성하기 위한 문서와 프롬프트 모음입니다.

## 진행 순서

| 순서 | 파일 | 하는 일 | 소요 |
|---|---|---|---|
| 0 | [`docs/01-api-key.md`](docs/01-api-key.md) | Anthropic API 키 발급 + 지출 한도 설정 | 20분 |
| 1 | [`prompts/01-infra.md`](prompts/01-infra.md) | WSL2 + Docker + n8n + Postgres + vLLM 구축 | 1일 |
| 2 | [`prompts/02-agents.md`](prompts/02-agents.md) | 에이전트 4명 정의 + 실행 러너 + 비용 안전장치 | 1~2일 |
| 3 | [`prompts/03-orchestration.md`](prompts/03-orchestration.md) | n8n 워크플로 + 24시간 스케줄 + 승인 게이트 | 1~2일 |

각 프롬프트는 코드블록을 **통째로 복사해서 Claude Code에 붙여넣으면** 됩니다.
프롬프트마다 "먼저 계획만 보여주세요"로 끝나므로, 계획을 확인하고 `진행`이라고
답하면 실제 파일이 생성됩니다.

## 하드웨어 기준

| | 현재 (1장) | 확장 (2장) |
|---|---|---|
| VRAM | 24GB | 48GB |
| 로컬 모델 | Qwen3-14B-AWQ (~9GB) | Qwen3-32B-AWQ 또는 30B-A3B-AWQ |
| 임베딩 | bge-m3 (~1.5GB) | 동일 |
| vLLM 인자 | 기본 | `--tensor-parallel-size 2` 추가 |
| 전력 | 약 400~450W | 약 700~800W |

확장 시 고칠 지점은 생성되는 파일에 `# ★ 2장 확장 시:` 주석으로 표시됩니다.

## 팀 구성

| agent_id | 역할 | 모델 | 비용 |
|---|---|---|---|
| `pm` | 목표를 태스크로 분해 | `claude-opus-5` | 높음 (하루 몇 번) |
| `worker` | 실무 수행 | `claude-sonnet-5` | 중간 |
| `grunt` | 요약·분류·초안 | 로컬 (3090) | 0 |
| `reviewer` | 산출물 판정 | `claude-opus-5` | 중간 |

**4명이 상한입니다.** 인원을 늘려도 성능은 오르지 않고 토큰만 늘어납니다.
품질은 인원 수가 아니라 (1) 명확한 완료 기준, (2) 검수 단계에서 나옵니다.

## 안전장치 요약

- 일일 지출 한도를 **Anthropic 콘솔과 코드 양쪽에** 건다
- 모든 재시도에 상한 3회 — revise 무한 루프 차단
- 외부로 나가는 행동(메일, PR 머지, 결제)은 전부 사람 승인 게이트 경유
- 장시간 세션을 유지하지 않고 매 실행마다 DB에서 상태를 재구성
- `scripts/kill-switch.sh` 한 방으로 전체 정지

## 자주 하는 실수

1. **에이전트 1명으로 끝까지 돌려보지 않고 4명을 한 번에 만든다** → 거의 항상 실패
2. **워크플로 6개를 한 번에 켠다** → 어디가 문제인지 알 수 없게 됨
3. **예산 게이트 없이 24시간 루프를 켠다** → 하루 만에 크레딧 소진
4. **시스템 프롬프트에 현재시각을 넣는다** → 프롬프트 캐시가 매번 무효화되어 비용 폭증
5. **`.env`를 커밋한다** → 키가 수 초 내에 스캔당함
